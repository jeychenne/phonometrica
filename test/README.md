# Phonometrica test suite

This directory holds the automated regression and validation suites
for Phonometrica. There are two cleanly separated tracks:

| Track            | Path             | What it tests                                  |
|------------------|------------------|------------------------------------------------|
| Engine tests     | `engine/`        | Scripting language: parser, compiler, runtime  |
| Statistics tests | `statistics/`    | Regression engine: GLM/GLMM fits vs R           |

The engine suite is pure phon — every test is self-contained and
aborts on the first failure via the built-in `assert` statement.
The statistics suite is a hybrid: an R script generates a JSON
reference once, then a phon test loads the JSON and compares
Phonometrica's `fit()` output against it.

## Running the suites

### Engine

```
phonometrica engine/run_all.phon
```

Or any individual test:

```
phonometrica engine/test_compound_assignment.phon
```

### Statistics — frequentist

First (re)generate the references on R:

```
cd statistics/frequentist
Rscript gen_reference_all.R
```

The R side needs `jsonlite` and `glmmTMB`. Per-family generators are
also available (`gen_reference_gaussian.R`, `gen_reference_beta.R`,
…) — useful when only one family changed and you don't want to wait
for the slow ones to refit.

Then run the phon side:

```
phonometrica statistics/frequentist/run_all.phon
```

A single per-family file works too:

```
phonometrica statistics/frequentist/test_gaussian.phon
```

## Conventions

- **Path resolution.** Tests use `get_script_path()` + `get_directory()`
  + `join_path()` (introduced in May 2026 alongside this suite) to
  find sibling files and the `data/` directory. No absolute paths
  appear in committed test code, so tests work on any OS and from
  any working directory.
- **Reference files.** JSON references generated by R live next to
  the test that consumes them, named `reference_<family>.json`. They
  are committed to the repo so a fresh checkout can run the phon
  side without R installed; regenerate them whenever R, the
  reference packages, or `_helpers.R` changes.
- **Tolerances.** Each `test_<family>.phon` chooses tolerances per
  model based on identifiability and engine differences. See the
  comments at the top of each test file for the rationale.
- **Coefficient name matching.** Phonometrica's `m.coef_names` and
  glmmTMB's `summary()$coefficients$cond` rows agree on naming for
  the formula syntax used here (`(Intercept)`, `vowelI`, `genderM`,
  `vowelI:genderM`, …). The harness matches by name, not by index,
  so a row-order difference would not cause spurious failures — a
  missing name would.
- **Random-effect SD names.** Phonometrica formats them as
  `sd(<term>|<group>)` plus a final `sd(residual)` for Gaussian
  mixed models (see `phon/application/data_table.cpp`'s
  `model_get_field("ranef_names")`). The R helper produces the same
  names verbatim.
